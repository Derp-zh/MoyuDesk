# C02 DSH监听

现行规则，2026-11-06。用户已专项授权实现DSH与Claude Code监听，采用原生结构日志只读方式。实际能力见[STATUS](STATUS.md)，旧探索从[更新日志](../history/CHANGELOG.md)追溯。

- C02-01：在阶段绑定窗口选择DSH及准确会话，保存后开始观察。只读DSH本机原生v4日志，不发送消息、代答、批准、改DSH配置或建立模型连接。支持DSH_HOME；缺组件、未知日志代次、断帧/序号缺口或来源不清均转待确认，不猜正文/UI文字或用更新时间推断执行。目录、结构来源、逐会话、原桌面生命周期及卡片保存分开报告。
- C02-02：原生approval/asked为等待批准，ask_user_question为等待回答，已确认plan/mode.active的exit_plan_mode为等待批准；非计划模式的失败调用不报批准等待；按准确请求编号逐条结清，超时pending及TOOL_OUTCOME_UNKNOWN保留等待。只回答或决定不算恢复；请求结清后的同轮实际assistant/message才确认恢复。正常整轮结束、整轮失败、用户停止进入待操作；未知结束理由不默认完成，forked种子结束不冒充当前轮终态。
- C02-03：沿用[C01](C01-Codex接入.md)的运行阶段、仅内置进行中/待操作两列、跨平台多阶段等待优先、跨断线/重连保持等待、旧轮次隔离、红点、编辑合并/保存及解绑重绑规则。同编号不同平台是不同来源；新绑定、归档恢复不继承旧保护，已完成/自定义列表不被后台移列。真正整卡恢复才清等待提醒，主动编辑保存清点保持。
- C02-04：正常监听无需DSH桥接服务；本机Node.js 24读取独立压缩帧。自动优先发现已安装DSH自带运行时，再检查用户运行时、继承/注册PATH及标准安装位置；有效手动值保留，失效/旧版/自检失败时回退其他已安装候选。初始化真实自检单候选限时，读取组件输出固定按UTF8解码，不受中文Windows启动代码页影响；正常观察不反复启动版本检查进程；正验证缓存不跳过当前文件/本机路径/MZ检查，文件变化或删除立即失效。未找到可用运行时只提示，不自动下载安装；不抓取原聊天正文或答案，不改DSH配置/自启/preserved-data。桌面操作按根AGENTS先获本次方便确认，测试任务使用隔离--data-dir，不重启当前Codex、不自动发布。

- C02-05：DSH独立子页保留只读检查连接、独立重新连接、测试已关联会话、打开已有程序及路径诊断修复；初始化改为M11统一三平台入口，初始化后继续恢复本机监听，球菜单及设置提供统一一键连接。启动自动只读检查桌面程序/本机目录/运行时，dsh前缀配置单独保存；路径停止输入600毫秒后合并检查，成功自动恢复监听。未运行、缺组件或临时检查失败时后台有界重检，原应用晚启动无需再次初始化；不自动打开原应用。目录及源读取失败不能影响Claude/Codex；已发现程序的证据不能被目录失败掩盖，错误展开诊断。权限不足时运行情况待确认，不把同名不可检查进程当已核实退出，也不自动开启第二个实例。

- C02-06：与Codex相同，拖动时显示目标真实会话名称；预览只读UIA独立标题文字，不开菜单或使用剪贴板，名称不作为身份。绑定窗口沿用M09右侧矩形悬停切换及未接入平台隐藏规则。从列表阶段名称或编辑/新建胶囊拖到原DSH侧栏准确会话，松开绑定。核对程序路径、用户、Windows Session和所属窗口；用目标自身“复制 Session ID”取得准确原生编号，不靠标题猜选，也不以看板内目录拖动替代原窗口。当前聊天区仅在同窗主会话唯一选中且取号期间身份保持时使用所属会话菜单；多面板或来源不明拒绝。结果以编号核对本机目录名称，平台+编号共同进入原编辑/保存链；配置变化、取消或旧绑定拒绝迟到结果。隐藏行按滚动视口裁切，空白/工具栏不猜。必要时临时显示所属行菜单，并在没有用户新输入/移动时恢复本次指针及侧栏滚动，不锁定指针；取号期间仅临时cloak本次看板来源窗口与绑定窗，finally解除，位置/内容和父子关联保留；原拖动期间显隐范围保持。剪贴板完整缓存且仅恢复本次序号；延迟格式只重试读取核对，不覆盖新的复制内容。窗口隐藏恢复、自动绑定窗、取消/改绑/解绑及红点规则沿用X01/M09/C01。
