# C01 Codex监听

正式名称为“Codex监听”，属于AI平台监听，包含绑定会话、读取会话状态及自动移列等功能。DSH监听、Claude监听与其平级且有独立设置子页；Windows系统通知归独立的“通知监听”。文档路径及既有规则编号保留，分类命名不等于未来平台已完成实际接入。

现行规则，核对日期2026-11-09。规则与“是否已实机验收”分开，结果见[当前状态](STATUS.md)。

Codex本地行为补充限定为纯被动观察：读取原客户端已经产生的本机文件或系统事件，前台增加只读UIA侧栏及当前会话输入控件，识别回答／批准／恢复的结构化行为及准确会话关联。用户已否决app-tools/read_thread/wait_threads及同类主动请求、订阅或要求Codex返回状态的路线；不能以“本机管道／零CLI”重新包装为新方案。Windows通知证明存在后台行为，不自动证明通知消失即恢复或通知字段足以唯一识别会话。保留现有监听，不改正式任务／配置、不重启原Codex；新实现和回归只用隔离目录，桌面操作每次开始前取得本次方便确认。

2026-11-04用户不接受本机订阅的流量不确定性，要求继续探索不依赖该订阅的Codex桌面端本地状态、功能及服务，同时保持可靠自动移列；同等条件下有监听流量最多接受无监听基准的两倍。用户指出此前每300毫秒获取任务列表造成高流量；Clash曾在订阅阶段观察到明显上传尖峰，但共享进程及其他活动使其来源和请求频率未定，不能排除订阅影响，也不能断言恢复原轮询。验收需记录对照条件、实际字节与时长、后台干扰和低基数情况；不能用受污染对照或未观测链路宣布达标。严格区分查询次数、Clash可见流量与绕过代理流量，不得为降低流量关闭自动移列或伪造状态。

- C01-01：优先原Codex桌面；手动选择准确已有会话，按阶段保存编号/名称和绑定代次。分类选中不代表连接。普通启动自动读取已有本机结构记录，不要求专用启动、观察端口或重开Codex，不创建/迁移/接管聊天、不发消息、不代答/批准、不改全局权限，不擅自关闭或重启Codex。没有退出后持续监测需求。
- C01-02：目录、传输、来源身份、逐会话实时能力、原桌面生命周期及实际卡片/持久化分别报告。独立历史服务、未加载、非本机host、目录成功或夹具不算实时。部分诊断退出3/完整passed=false不能改写为全通过。
- C01-03：仅内置进行中/待操作参与自动双向流转；其他四列、自定义列及未运行阶段不自动移动。多个运行阶段有尚未被用户确认的等待回答/批准、结果待检查、准确失败/中断事件时优先待操作，另一阶段运行不能盖过。正常结束待检查，不自动完成。
- C01-04：“补充识别 Codex 的待处理提醒”默认开启，请先在Codex客户端中开启通知权限，替代原Codex专用Windows通知补充。后台继续增量读取原客户端已有日志，前台按C01-14补充控件；日志按准确会话、轮次和来源限定的请求编号识别提问／批准及原响应；只有对应请求已处理且同轮出现后续执行证据才恢复。后台按准确编号识别，前台名称映射遵循C01-14；不连接Codex端口／管道、不发状态请求／订阅、不启动CLI或改日志级别。独立通知监听及声音功能保持。
- C01-05：已确认待处理保护跨断线/重连保持，不能因Unknown、另一阶段运行或旧终态清除。可信实际恢复并整卡回进行中时清时间红点；整卡仍待操作不清。新绑定、改绑、解绑重绑和归档恢复重置旧信任/保护；保留必要会话编号，拒绝旧绑定/epoch/序号及重复终态。主动编辑保存清任务红点保持，旧副本不覆盖后台。
- C01-06：当前准确轮次failed/interrupted、用户停止、整轮执行报错、明确额度用尽导致停止进入待操作，参与多阶段及重连保护。普通命令非零、临时错误重试、余额快照、断网/退出/Unknown本身不算整轮失败或额度停止。非重试error需准确当前轮次和明确额度枚举，不猜错误正文。
- C01-07：正常终态补查仅当前绑定已观察准确轮次；同一绑定运行时确认的轮次证据可跨重连Unknown保留，用于接收随后同轮终态，不跨绑定ID／代次／聊天、不覆盖更新轮次。重开看板仅对同一已保存等待绑定的准确TurnId补齐本机已提交终态，不把无关历史或新绑定当新结果；运行时观察标记仍不写入持久化。通道及身份有效时已接收的当前epoch终态不被全局无实时能力覆盖；真实断线仍待确认并保留等待。快停止补查需同epoch已有轮次及合法严格递增最新Unix秒水位，明确最新失败/中断且不同轮次才能直接待处理，不伪造运行/清点。首次历史、同秒、无基线、重连依据未重建均不猜。内部probe不允许外部Receive调用。
- C01-08：普通启动读取本机已存在的结构化SQLite记录，不连接Codex聊天管道，不启动额外CLI/app-server，不订阅、加载或接管聊天，不自动回退联网查询。目录与本机记录可读不等于原桌面实时完整性；不使用SourceIdentityVerified字段暗示已核验当前桌面进程身份。
- C01-09：后台只提取已有本机轮次状态、投影水位、文件大小时间与行为日志元数据，不查询聊天接口／历史服务，不保存或展示正文、答案或思考内容。投影未追平时有界暂存结构字段，待追平后处理，不让一个缺记录的聊天阻塞其他聊天。原响应发送本身不证明恢复，其他未处理请求继续保护；首开有界补齐当前准确在途轮次的请求／响应／执行，只发布净状态，不重放已处理等待或历史终态；新绑定不继承旧保护。日志轮转按启动身份关联，临时未发现保留游标；短暂投影滞后不抖动最近状态，标签恢复不当新执行。截断、积压或补齐超限保留等待并报告待确认。前台按C01-14核对结构控件；超出有界当前轮次补齐范围的旧请求、未知结构或断线期间事件缺失时明确待确认，不猜已恢复。持久化inProgress不等于已验证原桌面存活。
- C01-10：每次启动自动恢复本机轮次与已启用的本地行为补充。原客户端先开后开、日志暂不可读均持续重试；原客户端日志读取失败不关闭轮次监听，也不清已确认等待。更改补充开关仅重建看板自身观察器，不重启Codex或另外平台。旧Windows通知配置标识只为旧备份兼容保留，不启动Codex通知捕获；独立通知监听仍按N01。
- C01-11：初始化分别报告聊天列表、本机记录读取、具体已关联聊天的实时与提问批准能力；本机目录检查成功可完成记录监听准备，不要求旧管道连接成功，不能因此声称已核验原桌面身份。无绑定时明确尚未验证，不用握手冒充完整观察。测试已关联聊天只读取观察器已有快照，注明查看时刻，不另开连接、不订阅或刷新、不改任务、不发消息、不代答／批准。没有可信快照时报告待确认；绑定或配置变化丢弃旧结果。本次目录／路径／保存错误优先呈现，后台连接成功不能掩盖。
- C01-12：有效手动路径及原服务地址保留；正常目录和初始化目录检查直接只读经核实的本机元数据，不启动具有外联副作用的app-server，不依赖CLI或访问旧服务地址，不回退联网／聊天查询。支持本机CODEX_HOME及已支持的sqlite_home字面量，未知新版库／结构／配置明确失败。读取最新已提交WAL，及时释放连接，不猜缓存与远程会话。状态侧文件投影同样只读且只取结构：最新轮次与rollout_ordinal、投影已消费字节、rollout文件长度与写时间；不读聊天正文，投影落后即失败闭合。空目录、失败、取消不能长期缓存，并发加载合并，成功目录短时复用；目录与实时状态分开报告。

- C01-13：拖动绑定通过原桌面目标会话菜单取得严格本机codex://threads/UUID。核对同用户／Session／登记身份、来源阶段及落点，复制前完整缓存剪贴板并在序号未被外部改变时恢复；不发送消息、不回答／批准、不打开侧栏聊天、不启用观察端口或重启。新编号不继承旧绑定等待、请求和epoch；同编号仅名称／大小写更新保留有效保护。原编辑副本合并、其他阶段、撤销与红点规则保持。绑定成功与完整状态监测分开验收。

- C01-14：前台自动启用只读UIA补充，核对同用户／Session及登记身份的Codex窗口；后台继续原本机记录与行为日志策略，不新增Windows通知捕获。由现有本机目录的唯一当前名称映射绑定UUID，重名不猜，目录定时刷新且采样后核对最新已提交名称归属，重复侧栏入口合并，滚出可见区域不自动滚动或打开聊天。当前聊天的问题／批准可能不在侧栏显示，因此同时读取其准确对应的右侧原生请求表单，仅用控件角色、固定动作及请求容器结构，不分析问题／答案正文。问题未选答案时发送按钮禁用仍是有效等待，多问题“下一步”也保持等待；批准与回答分别映射。独立MTA线程以约400毫秒间隔读取，单次查询与总等待有界，控件失败不阻塞界面或后台源。离开前台、最小化、控件失效或代次变化后不使用旧缓存清等待；首份运行快照不能证明恢复，连续确认运行并结合本代等待变化或等待后的准确同轮执行。当前输入表单消失仅证明响应，必须再有最后一次确认等待之后的新执行，防止一直显示的“处理中”误清等待。仅解除当前绑定／当前轮次的前台等待，不批量删除其他来源的准确请求；实际恢复且整卡回进行中才清红点。若回答/批准后在下一次前台采样前最小化，后台亦核对同轮已追平且严格晚于最后等待样本的准确执行，释放该侧栏等待；旧执行、未追平及仅响应不释放。前台等待时间随原任务保存，改绑／归档恢复重置；准确终态优先，不强制补演中间运行。

- C01-15：会话身份始终为准确UUID，手动名称优先于旧自动标题；有绑定时每5秒被动刷新本机目录，同步正式阶段及编辑副本的名称并沿原链保存，无需重绑定，不改用户任务标题、绑定ID/代次或等待。较旧目录回调不覆盖较新时间戳名称，旧编辑副本不盖掉实时名称。名称仅用于展示/唯一UIA映射，重名不猜、缺名不清绑定。
- C01-16：侧边聊天属于主会话。只用本机attached_thread_parent_id、thread_spawn_edges及结构化spawn父ID解析多层关系，循环/缺父/冲突失败闭合，不凭标题或正文合并。主绑定下各来源保持独立UUID、绑定ID、turn/request及确认身份，单层平铺保存（最多128来源）；运行汇总仍是任一未确认等待优先，侧边提问/批准/完成/失败也使主卡待操作，主运行不能覆盖。来源恢复分别核对；改绑清来源并拒绝晚到，已确认旧事件不重放。目录明确否认旧亲缘时撤销该来源，目录暂缺的已知来源保留保护。
- C01-17：自动发现以可靠主UUID为候选，侧边执行不另建卡，活动任务/草稿/待提交同主去重；主显示名和原卡身份保持。只有本次实际发现的准确来源/轮次保留内存执行证明，补上很快结束的首读完成；不将持久化Running冒充当前执行，不将历史完成重放为新任务。右键提醒确认只写AiAttention事件身份，来源的真实等待/请求保留，其他阶段和时间红点不变。
