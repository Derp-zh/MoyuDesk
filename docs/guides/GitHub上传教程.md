# GitHub发布约定

本地整理不会自动上传。每次发布须有本轮明确授权；历史发布请求、曾经登录或旧网络检查不能代替本次授权与环境核对。

1. 核对本轮源码版本、验证回执、目标包和已有工作区改动。根Git是旧本地master，按 [MoyuDesk 仓库](https://github.com/Derp-zh/MoyuDesk)的 main 分支准备独立发布副本，保留远端现有内容。
2. 审查实际待提交文件及差异。源码、现行文档和必要验证工具同步；正式任务/配置、凭据、聊天、preserved-data、本机索引、测试输出和运行目录不上传。旧报告中的“没有敏感信息”只适用于原时点，不能替代新审查。
3. 在独立目录构建并验证完整便携包。Release同时提供完整ZIP和SHA256，不能只发主程序或沿用不匹配的旧包。
4. 按已确认远端、分支和版本同步源码与Release，再重新下载核对文件完整性、SHA256及远端提交/标签，保存实际回执。

当前源码、本地包和公开版差异只看[STATUS](../STATUS.md)，构建和验证见[工具说明](../../tools/README.md)。操作鼠标/键盘、前台或剪贴板仍需按[AGENTS](../../AGENTS.md)取得本次方便确认。

早期账号注册、代理端口、登录状态、文件大小及“直接上传整个文件夹”流程仅保留在[历史原文](docs/history/20261107-integration/GitHub上传教程.md)，不作为现行发布路线。
